# 覆盖率规律与归一化 v3

> 模型侧 | 2026-10-21 | 工具 `docs/scale-kit/coverage_model.py` · `ease_distribution.py` · `check_no_hardcode.py` · 自检 `selftest_coverage.py`
> **v3 修订（用户 10-21 口径）**：① 删掉"容差 = base + k×伸长%"这条**假设出来的线性式**；② 容差改成**面料 × 部位**二维、由品类绑定部位；③ 松量分布不预设形状，新增**橄榄型**判别。本文所有数值即当前生效值，v1/v2 的旧数已作废。

---

## 0. 用户口径（不许改形状）

1. **面料弹力大 → 覆盖率天然大**（机械效应，不是产品更好）。
2. **松量越大 → 覆盖率越大**：单调不减，**没有中间峰值，也不会在某个松量之后回落**。
3. **品类之间也有区别**：判"穿不穿得进"的部位不同、该部位的容差也不同，不许一张表通吃。
4. **有规律，但数据呈现不一定有规律**：代码里只放**可证的规律**（单调约束），不放拟合出来的函数形式，也**不放任何业务数值**。
5. 不假设正态；用经验分布直接数样本。**准确说：分布形状要先判**——常见是**橄榄型**（两头薄、中间厚），也可能是多簇/偏斜。
6. "太大没人要"是**偏好（需求侧）**的事，不许塞进体型覆盖制造上界回落。

---

## 1. 规律一：弹力 → 容差（只留单调，不留公式）

v2 写的是 `tol = base + k × 伸长%/10`。**已删除**：那是先假设了线性形式，再把系数标成 [D]——等于用假设假装数据；而且它是**一维**的，把"品类/部位"整个吞掉了。

v3 只声明一条**可证的规律**：

```
伸长率 ↑ ⇒ 紧侧容差 tight_tol_cm 不降      （单调约束，代码里强制自检，违反直接抛错）
```

容差数值来自三处，**越具体越优先**，都没有就报错（不兜底）：

| 优先级 | 来源(文件/字段) | 粒度 | 现状 |
|---|---|---|---|
| ① | `data/fabric_tol_obs.json`（面料×(部位)×伸长率 → 实测可忍受的紧侧偏差） | 面料×部位 | **尚无数据**（文件不存在≠错误，会标 `no_file`） |
| ② | `config/category_fit.json` → `tight_tol_cm{部位}` | 品类×部位 | tee/pants/skirt 有值；shirt/jacket 空 |
| ③ | `config/fabric_stretch.json` → `tight_tol_cm` | 面料整体 | 8 个面料全有 |

①若存在，用 **PAVA 保序回归**拟合：只在伸长率轴上强制单调，**函数形式由数据决定**（噪声输入会被压平，不会照抄）。样本 < `min_obs` 按"样本不足不更新"处理，回落②/③并在输出里标 `source`，不是静默兜底。

**为什么这不算"又编了一套数"**：③ 的数值是 v2 旧经验式 1.0cm + 0.01cm×伸长% **一次性落表**的结果（保留是为了历史结论可复现），出处写在 `fabric_stretch.json` 的 `tight_tol_note`，全部标 [D]。占位数值进配置、规律进代码——两者分离，数据到了只换配置。

当前③（伸长率 → 容差，cm）：

| 面料 | 无弹梭织 | 弹力梭织 | 罗马布 | 单面汗布 | 压力衣 | 罗纹 | 瑜伽裤布 | 泳衣布 |
|---|---|---|---|---|---|---|---|---|
| 伸长% | 2 | 10 | 18 | 25 | 35 | 40 | 45 | 55 |
| tol | 1.02 | 1.10 | 1.18 | 1.25 | 1.35 | 1.40 | 1.45 | 1.55 |

## 2. 规律二：整件判定取**最紧的围度部位**

一个部位松、另一个部位紧，整件还是穿不上——所以判定不是取平均，而是：

```
品类 → 关键部位里挑**围度类**（girth）的 → 逐个解析容差 → 取 min 作为该品类该面料的紧侧容差
绑定部位 = argmin                                   （code: category_tol()）
```

**只认围度类**是关键：长度/裙长/内长/袖长/肩宽属"可改"或"版型"问题，塞进来会把"裙长短 1cm"算成穿不上。维度表在 `category_fit.json/part_dimension`，可判维度在 `wear_gate_dimensions = ["girth"]`（配置，不是代码）。

当前（面料=单面汗布 25%，即 T 恤布）实际输出：

| 品类 | 参与判定部位 | 绑定部位 | 紧侧容差 | 来源 |
|---|---|---|---|---|
| T恤/针织 | bust, waist | waist | 3.00cm | 品类×部位 |
| 西裤 | waist, hip, thigh | thigh | 1.25cm | 面料整体（部位未标定） |
| 半裙 | waist, hip | waist | 2.00cm | 品类×部位 |
| 衬衫 | neck, bust | neck | 1.25cm | 面料整体（部位未标定） |
| 外套 | bust | bust | 1.25cm | 面料整体（部位未标定） |

**已知缺口（挂账，不掩盖）**：shirt/jacket 的部位级容差还没标定 → 回落面料级（1.25cm），对外结论会**系统性偏保守**；pants 的 thigh 亦然。补法只有一个：拿订单/退货里"实际紧了多少还留着穿"的样本做①，不改代码。

## 3. 规律三：体型覆盖单调不减，上限 100%

物理非对称：**大了能穿（松侧无上界）/ 小了穿不进（紧侧有界）**。

```
穿得进 ⇔ 该部位需要的松量 ≤ 松量 + 紧侧容差
体型覆盖 C(E) = P(需要松量 ≤ E + tol)          ← 经验 CDF，非参数
```

- C(E) **单调不减**，最大值永远在最松端；代码带自检，出现回落直接抛 `AssertionError`（自检会把曲线故意打坏的场景跑一遍）。
- **需求样本按品类分池**：外套的松量需求和 T 恤不是同一个分布（外套要叠内搭）。`load_needs(category)` 读 `data/ease_needs.json`，**品类不混池**、文件缺失直接报错，不用合成样本顶。
- 决策量不是覆盖率峰值（越松越高、峰值无意义），而是**阈值穿越**：

```
E* = min{ E : C(E)/C_max ≥ 目标比例 }          目标比例 = 0.95（配置）
```

## 4. 分布形状：先判形状，再取点（新增橄榄型）

真实松量数据里最常见的不是多簇，而是**橄榄型**：中间厚、两头薄、近似对称单峰。旧口径一律按"多簇/反正态"处理，是把一种情况当成了全部。

`shape_profile()` 判五类，阈值全在 `model_params.json/distribution_shape`：

| 形状 | 判据（配置项） | 取点规则 |
|---|---|---|
| `olive` 橄榄型 | 单峰 + 两端密度 ≤ 峰值×0.35 + 偏度 ≤ 0.8 | 取**平台中心**；均值落在平台外就明说"取均值会偏" |
| `multi_modal` 多簇 | 两峰之间谷/峰 < 0.55 | 单点覆盖不了 → **必须分款**（交给 `group_preference`） |
| `skewed_*` 偏斜 | \|偏度\| > 0.8 | 只报分位数 + 平台，不报 mean±sd |
| `flat` 平坦 | 其余 | 同上 |
| `insufficient` | n < 60 | **不报点** |

实测（合成样本，只验判别力不是业务结论）：橄榄样本 → `olive`（两端密度 0.005/0.036，偏度 −0.05），推荐点 5.75cm ∈ 平台 [5.5, 6.0]，均值 5.93 落在平台内 → 此时均值可用；多簇样本 → `multi_modal`（谷/峰 0.015），拒绝给单点。

**橄榄型不改变体型覆盖**：形状属于偏好/需求侧（可非单调），体型覆盖仍是物理单调曲线。两条曲线各管一件事，混用就错。

## 4.1 品类各自一条分布（位置与形状都不同，禁止合并）

"不同品类不同分布"不是一句原则，是**强制**（`load_needs(category)` 不给你混池的口子）：

| 事实 | 后果 |
|---|---|
| 同一人群，外套的需求整体右移（要叠内搭），T恤最窄，裤/裙看另一个部位 | 每个品类**单独**拟合、单独判形状、单独取点 |
| 品类之间的形状可能不同（一个橄榄型、一个偏斜） | 形状也要**逐品类判**，不许拿一个品类的形状套另一个 |
| 两个品类点差 ≥ `distribution_shape/cross_category_min_gap_cm`（1.0cm） | 必须**分款/分版**，不给"折中一个松量" |

实现：`ease_distribution.compare_categories([...])` → 逐品类 `shape/point/plateau/median/CI`，并给出 `must_split` 与 `shapes_differ`。
自检实测（合成样本，只验机制）：tee 橄榄型点 5.25cm（平台 4.5–6.0），jacket 橄榄型点 13.0cm（12.5–13.5）→ `gap 7.75cm → must_split`；shirt 只有 40 条样本 → `insufficient`，**不报点**。

**禁止**：把多品类样本倒进一个列表算覆盖率。那会把两个峰拉成一个大胖峰，覆盖率先被高估再被当成"普适最优松量"。

```

```

清单不是"已经合规"，是**待还的债**：这批文件（size_fit/category_fit/recommend/feedback_loop…）里还散着阈值与系数，等下一轮清理再纳入闸门。

## 7. v1/v2 错在哪（留档）

| 旧写法 | 问题 | 现在 |
|---|---|---|
| 正态 + 双侧窗口 `[E−8, E+1]` | 造出 8cm 峰、12cm 回落的假结论 | 经验 CDF 单侧判定 + 单调自检 |
| `组合覆盖 = 体型 × 偏好` 取乘积峰值 | 乘积峰值仍是"中间峰" | 决策 = 归一化达标的**最小松量**；偏好只用来分款 |
| `tol = base + k×伸长%/10`，k=[D] | 先假设线性形式，再用 [D] 掩饰没有数据；且只有面料一维 | 只留单调约束；观测用 PAVA 拟合；容差是面料×部位二维，品类绑定 |
| 一律按"多簇/反正态" | 把"橄榄型"当异常 | 先判形状再取点；橄榄型取平台中心 |
| 容差只有一个全局 base | 品类之间串味；长度维度混进"穿不穿得进" | 围度类部位 min；长度/肩宽不参与 |

## 8. 限制（说清，不假装）

- tol 仍全部是 [D]：**占位数值**，出处与替换方式写明在配置；真实值只能靠订单/退货回归。
- 松侧"完全无上界"是理想化：极端松量会掉肩/掉裆，属**品类结构约束**，在选码层判，不在覆盖率曲线里打折。
- 圆截面近似：人体是超椭圆，椭圆度高时围度容差误差 3–8%。
- `data/ease_needs.json`、`data/fabric_tol_obs.json` 尚未入库；没有真实样本前，覆盖率**不许对外报百分比**。
